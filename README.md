# МАИ Вики — студенческая база учебных материалов

**Неофициальный студенческий прототип.** Общественный проект «Обучение служением», кафедра №515, МАИ, 2026. Сайт **не заменяет** официальные образовательные системы, расписание, указания преподавателей и другие каналы МАИ. Пилот: 1 курс, институт №8, ФИИТ, М8О-111БВ-26. Период: 26.10.2026–28.11.2026.

## 1. Как запустить

Проект написан на HTML + CSS + JavaScript без фреймворков и внешних библиотек.

**Самый простой способ:** распакуйте архив и откройте `index.html` в браузере. В отдельных браузерах при открытии с `file://` может быть ограничено локальное хранение файлов (IndexedDB).

**Рекомендуемый способ для проверки всей функциональности:**

```bash
cd mai-wiki-site
python3 -m http.server 8000
```

Затем перейдите на `http://localhost:8000`. Вместо Python можно использовать Live Server в VS Code или любой статический HTTP-сервер.

Интернет не требуется для интерфейса и демо-данных. Для открытия внешних ссылок интернет может понадобиться.

## 3. Как менять карточки дисциплин

Все 10 карточек создаются в `js/data.js`, строка:

```js
const demoDiscipline = (n) => ({ ... });
// ...
disciplines: Array.from({ length: 10 }, (_, i) => demoDiscipline(i + 1)),
```

Чтобы добавить настоящую карточку, замените один из элементов в `disciplines` **объектом, данные которого подтверждены источниками**. Для остальных 9 демо-записей можно сохранить функцию-заготовку:

```js
disciplines: [
  {
    id: 'course-01', // уникальный, неизменяемый идентификатор
    demo: false,
    cardNumber: 1,
    name: '[вставить подтверждённое название из учебного плана]',
    course: 1,
    semester: '[семестр]',
    direction: 'ФИИТ',
    groups: ['М8О-111БВ-26'],
    teacher: '', // только если требования преподавателей надо различать
    status: 'needs-clarification',
    description: '[описание]',
    resources: [
      { author: '[автор]', title: '[ресурс]', url: '', linkCheckedAt: null }
    ],
    requiredWorks: [
      { name: '[работа]', source: '[источник]', sourceUrl: '' }
    ],
    admission: '[допуск]',
    grading: '[критерии]',
    deadlines: '[сроки]',
    officialSource: { title: '[название официального источника]', url: '' },
    publicationBasis: '[основание размещения]',
    lastCheckedAt: null,
    checkedBy: '',
    nextCheckAt: null,
    history: [],
    keywords: ['[дополнительное ключевое слово]']
  },
  ...Array.from({ length: 9 }, (_, i) => demoDiscipline(i + 2))
],
```

В реальной записи замените значения в квадратных скобках достоверной информацией. Не ставьте статус «проверены», если подтверждения нет. Если у преподавателей разные требования, создавайте отдельные записи и указывайте соответствующего преподавателя и группы.

**Статусы карточек:**

- `general` — «Общие ресурсы» (не подтверждает требований);
- `verified` — «Требования проверены»;
- `needs-clarification` — «Требует уточнения»;
- `outdated` — «Нуждается в обновлении».

**Даты:** формат `YYYY-MM-DD`, например `2026-11-26`, или `null`, если проверка отсутствует. История изменений:

```js
history: [
  {
    date: '[YYYY-MM-DD]',
    change: '[что изменено]',
    reason: '[основание]',
    editor: '[ответственный]'
  }
]
```

**Ссылки:** только `http://` или `https://`. При отсутствии проверенной ссылки оставьте пустую строку. Не добавляйте неподтверждённые сроки или требования ради заполнения карточки.

## 4. Что работает в демо

| Раздел | Статус |
|---|---|
| Главная, нижняя навигация, мобильная/десктопная вёрстка | Работает |
| Светлая и тёмная тема с запоминанием выбора | Работает в браузере |
| Поиск по полям карточек, ссылкам, ключевым словам, `ё/е` | Работает на клиенте |
| Каталог: 10 заготовок, фильтры по семестру и статусу | Работает |
| Подробная карточка, история, источники, статусы | Показывает демонстрационные поля |
| FAQ: 8 раскрывающихся вопросов | Работает |
| Предложение: номер, дата, статус и отправка в локальную очередь | Работает в одном браузере |
| Вложение до 5 МБ | IndexedDB, **только в этом браузере** |
| Локальная модерация: фильтр, решение с обоснованием, журнал | Работает **без защиты доступа** |
| Показ локально принятых предложений на странице дисциплины | Работает в этом браузере |
| Планировщик: добавить, выполнить, удалить | localStorage, только это устройство |
| Обратная связь без контактных полей | Локально сохраняется, видна в панели модератора этого браузера |
| Страница «О проекте» с командой и границами пилота | Работает |

Открыть локальную страницу модератора: `#moderator`, например `http://localhost:8000/#moderator`. Ссылка также приведена мелким текстом на странице «О проекте». Панель намеренно отсутствует в пяти пунктах нижней навигации. **Скрытая ссылка не является аутентификацией**: в демо любой посетитель с доступом к данному браузеру может изменить локальные записи.

Целевой срок первого решения — **2 рабочих дня**, рассчитывается по понедельникам–пятницам без учёта праздничных дней. Это целевой срок работы людей, а не автоматический механизм исполнения.

## 5. Что НЕ готово к реальной работе

1. **Нет общего хранилища.** Предложения и отзывы разных пользователей не поступают в единую очередь. Они сохраняются локально и могут исчезнуть после очистки браузера.
2. **Нет защищённых учётных записей модераторов.** Демо-страница доступна по ссылке. Для публичного запуска требуется авторизация и ролевой доступ.
3. **Принятие предложения не изменяет `data.js` автоматически.** Одобренный материал отображается только как «принятый локально». Для постоянного каталога нужен редактор, сервер или ручное подтверждённое обновление файла.
4. **Файлы доступны только в IndexedDB отправившего браузера.** Другой пользователь или модератор с иного устройства их не получит. Для совместной работы необходимо безопасное файловое хранилище и проверка разрешений.
5. **Нет реальных учебных данных.** Все 10 карточек — явные заготовки со статусом «Требует уточнения».
6. **Ссылки на анкеты — `#`.** Команда должна вставить согласованные URL первичной и итоговой форм.
7. **Нет проверки автора и лицензии автоматически.** Модератор обязан проверить основание размещения вручную.
8. **Нет независимой оценки влияния проекта.** Полезность и скорость поиска должны оцениваться по методике пилота. Демо ничего не доказывает.

## 6. Как подключить реальное хранилище

### Вариант A: Google Forms + Google Sheets (минимальная настройка)

1. Создайте отдельную форму предложения материала без сбора адресов электронной почты и ФИО. Включите поля из формы сайта: дисциплина, тип, описание, URL/библиографическое описание, источник и основание размещения, согласие на модерацию.
2. Свяжите ответы с Google Sheets. Ограничьте доступ к таблице сотрудникам команды/модераторам.
3. Если нужны вложения, учитывайте, что стандартная загрузка файлов в Google Forms может требовать входа в Google-аккаунт и собирать дополнительные идентификаторы. Для анонимного пилота предпочтительнее ссылки и библиографические описания либо другое настроенное хранилище с контролем конфиденциальности.
4. Замените локальную форму ссылкой на внешнюю форму **или** создайте безопасный серверный посредник (например, Apps Script Web App), который принимает данные без публичного раскрытия таблицы. Не встраивайте ключи доступа и закрытые идентификаторы как секреты в клиентский JavaScript.
5. Для отображения статусов нужна отдельная система выдачи непривязанных к личности номеров и безопасный API. Google Forms/Sheets сами по себе не обновят статусы в интерфейсе сайта.

### Вариант B: Supabase / Firebase (полная интерактивность)

1. Создайте таблицы/коллекции `disciplines`, `resources`, `proposals`, `proposal_decisions`, `feedback`, при необходимости `file_assets` и `card_changes`.
2. Настройте доступ: анонимный пользователь может **создать** предложение; чтение всей очереди и смена статуса доступны только авторизованному модератору. Запретите клиентам изменять роль, статус или чужие записи. В Supabase обязательно задайте RLS-политики; в Firebase — Security Rules.
3. Подключите хранилище вложений с проверкой размера, типа файла, оснований размещения и разрешений на скачивание. Не делайте чужие материалы общедоступными по умолчанию.
4. Замените вызовы `readJson` / `saveJson` в `js/app.js` на обращения к защищённому API. Перед публикацией перенесите каталог с `js/data.js` в одобренные серверные записи либо поддерживайте экспорт в публичный JSON.
5. Реализуйте авторизацию модератора, журнал решений на стороне сервера и проверку вводимых данных на сервере. Для честной защиты пилота заранее опишите срок хранения и порядок удаления анонимных данных.
6. Планировщик можно оставить локальным: он не требует серверной синхронизации и не должен передавать личные учебные задачи без отдельного решения.

## 7. Как опубликовать сайт

### GitHub Pages

1. Создайте репозиторий, загрузите в него `index.html`, каталоги `css`, `js`, `assets` и `README.md`.
2. Откройте **Settings → Pages → Build and deployment → Deploy from a branch**.
3. Выберите ветку `main`, каталог `/ (root)`, сохраните. Адрес появится в Pages.
4. После публикации проверьте ссылку, мобильное отображение и формы. **Статическое размещение НЕ добавляет серверное хранение и защиту модератора.** Для публичного пилота лучше отключить/заменить локальную форму, пока не подключён общий приём предложений.

### Netlify / Cloudflare Pages

Загрузите распакованную папку проекта как статический сайт или подключите Git-репозиторий. Сборка не нужна; корнем публикации должен быть каталог с `index.html`. Убедитесь, что `js/data.js` доступен по относительному пути.

## 8. Приватность, честность и ограничения

- Формы **не запрашивают** ФИО, телефон, почту. Однако пользователи должны самостоятельно не включать личную информацию в свободный текст, ссылки и файлы.
- Нет внешних шрифтов, аналитики, трекеров или CDN. Внешние ресурсы открываются только по действиям пользователя.
- В демо данные сохраняются в localStorage / IndexedDB текущего браузера; это **не** безопасное многопользовательское хранилище.
- Очистка данных сайта может безвозвратно удалить задачи, предложения, прикреплённые файлы, отзывы и журнал решений.
- Нельзя называть платформу официальной или утверждать, что гипотеза подтверждена без результатов пилота.
